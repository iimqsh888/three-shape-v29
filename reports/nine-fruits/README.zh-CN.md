# 九果迷阵：链上重放技术样板

结论：6×6、无重力、无补充、允许水果与空格相邻交换的规则，可以采用本地推演、一次提交、链上重放验证。当前样本无需引入服务器成绩签名或零知识证明。长路径可以分段，但分段总 Gas 更高。

这是独立研究样板，不是完整赛季合约，不持有资金、不生成真实排名、不铸造勋章；没有向 BSC 测试网或主网部署。现有 Game、Token、Reserve、Liquidity 合约及线上前端均未修改。

## 实际接口核对

原有 `ThreeShapeNFTV29` 是 ERC-721，提供 `ownerOf(tokenId)` 和 `kind(tokenId)`，种类为 1–8 水果、9 Star；没有每种 NFT 的钱包余额接口。正式入口可让钱包提供九个 tokenId，合约逐个核对持有人、种类并用位图确认九种全部覆盖，不需要扫描所有 NFT 或修改原合约。

原有 `.ai` 门槛为 registry.balanceOf(wallet)>0。3SHAPE 为 OpenZeppelin ERC-20，当前实现 decimals 为 18；新模块只通过授权后的 transferFrom 收费，无权调用旧合约的 mintPlayer/mintLP。勋章仍应使用独立合约。

## 样板结构

- `puzzle/engine.mjs`：完整棋盘扫描、合法移动、同时消除和重放的离线基准实现。
- `puzzle/generate.mjs`：固定种子逆向构造，生成时保留清空路径证书，再正向重放验收；找不到合格结果直接失败，不发布未知有解性的棋盘。
- `puzzle/solve.mjs`：独立的有预算束搜索，记录搜索节点、提供已验证解法。达到预算只报告 budget-exhausted，不声称无解、最短或唯一。
- `scripts/puzzle-solve.mjs`：Agent 可通过本地命令读取棋盘 JSON 并得到移动序列；不是已接入的钱包或对话平台工具。
- `contracts/puzzle/NineFruitsVerifier.sol`：只读纯验证器。36 格各四位，棋盘占 144 位；每步用两个字节表示零起始格子编号。没有游戏步数上限。
- `contracts/puzzle/NineFruitsSessionHarness.sol`：仅用于本地测量的分段验证合约。中间状态绑定 msg.sender，单笔最多 64 步；累计步数不限。不验证 NFT、门票或赛季发布权限，绝对不能用作实际比赛入口。
- `test/puzzle/verifier.test.mjs`：种子复现、有解证书、前端/JS/Solidity 逐步一致性、交叉同时消除、非法输入、随机合法路径、分段状态归属及失败回滚。

Solidity 利用“每一步之前不存在三连”的不变量，只检查交换的两个位置所涉及的行列，先合并消除集合再清除。离线基准仍全盘扫描，测试比较两种独立算法，避免只测试同一段实现。

## 建议的正式方案

优先一笔交易验证、收取步数费用并登记名次，减少签名和交易数；长路径按当前网络预算估算后才采用分段。64 步只是本地分段样板的参数，不是玩家游戏上限或已定的正式限制。最终参数要在完整赛季结算实现后测 BSC Fork，不能仅凭本样板定死。

正式多段模式必须把初始棋盘与赛季/挑战/钱包绑定，中间棋盘由合约自己计算和保存；不能让调用者任意上传一个“快清空”的中间棋盘。最后一步验证清空、收取全部累计步数费用、登记排名必须原子完成。未结算的分段不占排名。BNB/赞助代币分别自行领取。

目前的离线求解保证有解依赖发布工具和管理者按流程操作；不等于链上证明有解。样本文件公开了完整答案，仅用于研究，不能直接用于带奖金比赛。确定性公开棋盘仍可被复制和提前求解；身份绑定、提交保护和机器人竞争需要在正式比赛合约中单独处理。

## 复现

在项目根目录执行：

```sh
npm run test:puzzle
npm run benchmark:puzzle
npm run solve:puzzle -- reports/nine-fruits/seed-2907.json
```

项目原始依赖锁文件的 Ganache 嵌套 fsevents 在本 Linux 环境导致 npm ci 报 EBADPLATFORM；本次使用 `npm install --omit=optional --no-package-lock --no-audit --no-fund` 安装现有依赖，未修改依赖版本或锁文件。Ganache 的 µWS 本地模块与 Node 版本不匹配，自动回退 JS 实现；EVM 测试正常执行。

## 后续边界

本阶段没有实现：门票/放弃/重开、结算扣费、领奖、防重复排名、赞助代币兼容名单、8 小时发布及超时退回、永久勋章、抢跑保护。它们不能被本报告中的通过结果替代。下一阶段在这些规则定稿后，围绕现有验证器新增独立赛季模块，再做完整资金和权限测试。
