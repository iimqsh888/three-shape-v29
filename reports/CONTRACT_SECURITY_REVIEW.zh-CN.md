日期：2026-11-09。范围为本地源码审查、solc 编译、Ganache 可执行回归；不是第三方审计或 BSC Fork 结论。

**结论：发现 1 项高影响初始化可用性问题，不建议在处理前进行真实资金上线。生产合约源码本轮未修改。**

## H-01 首次 LP 初始化可被小额捐赠和公开同步阻断

严重性：高，影响初始化／流动性可用性。已在本地复现；实际 PancakeSwap V2 与 BSC USDT 环境仍需 Fork 复核。

位置：ThreeShapeV29.sol 第 251–259 行，尤其第 253 行的 `a==0 && b==0 && pair.totalSupply()==0`；购星捕获失败位于第 207 行。

前提：部署的交易对存在，但 Liquidity.initialized 仍为 false；交易对具有 V2 风格的公开 sync 操作。

复现 SEC-01：

1. 普通外部账户获得测试 USDT 后向交易对转入 1 个最小单位；不修改虚拟机存储，不需要 Game、Liquidity 或部署者权限。
2. 调用公开 sync，使储备成为 `(0, 1)`，LP 总量仍为 0。
3. 合格玩家连续购星两次。两次购买均成功、收款／NFT 发放均继续，但都触发 LPAttemptFailed，initialized 保持 false，LP 铸币为 0。
4. 两次购星后 Reserve 增加 16 USDT，2 枚 Star 对应的本笔 LP 额度已记录为过期。合约没有独立初始化／重试入口。

测试 Pair 的 sync 只按实际 ERC20 余额更新储备，模拟 V2 的公开行为；这不等于已经完成真实 PancakeSwap Fork 验证。测试 USDT 为 6 decimals，1 个最小单位是 0.000001 USDT；BSC 真实 USDT 的 decimals 必须实读，不套用测试精度。

影响：不是已证实的直接盗币；攻击者可使预期的自动建池流程持续拒绝，同时后续购星继续收费。首次加池的空池假设不能只靠前端检查保证。

修复方向：评审原子部署／初始化流程，或评审兼容捐赠／非空储备的初始化方案。不能仅删除 require 或将 initialized 强行改为 true；也不建议增加任意管理员铸币或提款权限。修复需保持本项目既定初始价格、LP 单笔预算、80/20 分账和烧毁 LP 的边界，并在真实 V2 Fork 上验证。

本轮按“检查与测试”范围保留生产规则，没有擅自实现新初始化逻辑。

## C-01 持有 .ai ID 不等于不可复用的身份额度

分类：有条件的身份设计限制，不直接认定真实 Agent ID 合约存在漏洞。

位置：第 107–109 行按当前余额判断资格；freeClaimed 和 starsBought 分别在第 91–92 行按钱包地址记录。

SEC-08 使用测试专用可转让 ERC721 Registry：钱包 A 免费领取后，将同一个身份 NFT 转给 B，B 也可免费领取。说明在身份可转让的前提下，同一个 ID 可以让多个钱包依次满足余额门槛。

真实 `.ai Agent ID` 是否允许这种转让／迁移，本轮没有验证；如真实 ID 不可转让，此复现前提不成立。当前实现符合已确认的 balanceOf 钱包持有规则，但不能把它宣传成“每个身份唯一额度”或完整防刷。是否改为身份编号绑定属于规则变更，本轮没有修改。

## L-01 canBurn 对不存在／已销毁 NFT 会回退

严重性：低，主要是查询可用性与 Adapter 处理。

位置：第 147 行直接调用 ownerOf。SEC-05 证实不存在的 ID 会回退，而不是返回 false。重复、他人 NFT、错误长度和不同普通水果提交都不能烧毁资产。

Adapter 应明确将不存在／已销毁 ID 的查询错误处理为不符合条件并重新读取收藏。不可把只读异常误报为已销毁、已成功或已结算。本轮未改查询 ABI 或业务语义。

| SEC-05 NFT 验证 | 重复 ID、错误数量、他人持有、混合普通水果和不存在 ID 均不能完成销毁 |
| SEC-06 付款与限额 | 低 maxPayment、缺少 allowance、累计购满 6 枚后的额外购买均回退，不部分更新余额／额度 |
| SEC-07 领奖保护 | minAmount 高于可领金额时回退；份额耗尽时领奖／继续拒绝，不能铸币或从匹配状态结算 |

SEC-07 的终局份额使用编译器 storageLayout 定位的隔离夹具设置为 55,000；没有宣称运行了 55,000 个真实玩家。SEC-01 的攻击步骤没有使用该存储夹具。

## 代码整洁度

权限分工明确：Game 铸造玩家奖励和水果；Liquidity 铸造受限 LP Token；Reserve 仅向 Liquidity 放款；依赖地址 immutable，部署工厂只允许部署者初始化一次。源码未发现面向任意管理员的 mint／withdraw／修改 cap 入口。该结论限定于本地已审查源码，不代表任意部署地址或第三方 Router 都可信。

可维护性仍有改进空间：

- 五个业务合约集中在一个文件，多处一行包含多条语句，不利于逐行审计；建议后续只做格式化与按职责拆文件，并验证行为／ABI 不变。
- IGameLPV29 是空接口，只用作地址类型；需说明其意图或在独立清理中移除。
- 对状态迁移、LP 预算过期、失败不回退购星等边界补充 NatSpec。
- LPAttemptFailed 不携带失败原因，实际接入应同时核实购买事件、LP 事件和链上状态；不能只看交易 status=1 就宣称加池成功。
- 保留带编译器版本、优化参数和源码哈希的复核记录；部署时还应核对运行字节码。

## 经济模型核对边界

既有份额／奖励 cap／LP cap／千枚价格边界的基础用例通过。总量与分账算术一致不证明市场价格、交易深度或长期经济健康。现货池比率、一次性 LP 预算过期、Reserve 余额可能滞留属于已经记录的机制，不擅自引入新规则；H-01 是在其基础上单独复现的初始化阻断问题。
