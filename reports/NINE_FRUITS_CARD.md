# Nine Fruits seasonal deck preview

The V2.9 portal opens one full current-season card at the top, starting at S1. Only a matching successful settlement receipt retires that card with a shrinking downward animation, adds its medal to the bottom Completed area, and expands the next full card in the original position. Progress is strictly S1 → S2 → Sn. Clearing locally, pending transactions, failures and mismatched receipts do not advance the deck. Historical mini cards open their own claims and explicitly selected rankings without replacing the current top card. The default Ranking tab follows the current season.

Each card shows its N-BNB pool, sponsorship status, board-upload status, eight-hour publication target window or delayed-opening state, and optional token rewards. S1 is a published example. S2 starts unfunded/unpublished; funding does not invent a board or unlock play. Only global opening of Sn enables funding Sn+1; S1 is the initialization exception. Sponsor eligibility is independent of personal completion. The waiting funded season retains the sole sponsorship window until explicit admin publication/opening; delays never enable funding a later season. The form explains the next locked season. Demo settings offer an explicitly simulated sample-board publication control, disabled until fully funded.

The sponsorship form now includes an optional one-token BSC reward panel: contract address, explicitly simulated compatibility check, fixed tokens per person for ranks 11–100, and an exact amount×90 total. Changes to the address invalidate the check. Zero values, excessive precision and uint256 total overflow block funding. Inline fields list BNB, title, per-person amount, total and address before direct funding. On simulated funding, all configuration locks. No token metadata or compatibility is actually read from BSC; DEMO/18 decimals are UI placeholders.

Gravity-v1 remains shared with the research engine: adjacent fruit swaps must match, stars block gravity, cascades do not add moves, no refill. Entry and settlement remain simulated. Active attempts have no expiry and persist per season in the current browser. Explicit abandonment forfeits the demo ticket and requires new entry. This test release intentionally resets earlier preview progress and sponsorship using a new v3 storage namespace; older demo keys are cleared on opening. New v3 progress persists between visits.

The settlement gateway is injectable, but the shipped preview uses explicitly labeled delayed demo receipts. A future live adapter must verify the wallet’s authoritative completion event/state after a successful chain receipt; this UI boundary is not itself chain verification. Pending records survive reload, do not auto-resubmit, and require reconciliation. Chain transport errors retain an unknown pending state. Demo settings can select a failed receipt to inspect the non-advancing state. Reset invalidates late asynchronous receipts.
