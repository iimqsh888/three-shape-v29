# 通用 Agent 与用户钱包接入

Three Shape 是独立链上游戏。网站、Skill、HTTP 只读接口、ABI 适配和 React 卡片不依赖模型品牌、聊天平台账户或供应商专属工具。静态网站由项目维护者部署到自己的服务器，公开资源使用同源相对路径。

## 能力分层

1. 只有 Skill 文本：解释规则、生成可编辑交换／收购帖；余额、资格和交易状态不可凭空生成。
2. 支持 HTTP／链上读取：查询指定网络与可信部署的收藏、身份、挑战、奖励和订单；用户输入地址仅允许公开查询。
3. 支持用户签名：接入标准 EIP-1193 钱包或宿主注入的用户 Signer。预览本次具体操作，获得明确确认后请求签名，等待链上确认再刷新结果。
4. 支持富 UI：可选嵌入 ThreeShapeCard；仅支持文字时显示同一结构化结果的 Emoji 面板。工具调用能力不代表宿主具备卡片渲染能力。

## 钱包验证与确认

钱包地址、网络和签名能力来自当前用户授权的真实会话。读取官方 .ai Registry 验证持有资格，不能把网站登录、模型输出或测试身份当成官方身份。现有五个游戏写操作仍按合约检查调用钱包，规则不改。

转赠输入 .ai 后自动解析，预览指定 NFT、数量和接收人，提示不可撤回，并执行二次确认。签名前再次核对解析和所有权；变化使旧确认失效。实际钱包要求显示完整地址或权限时必须保留，不绕过钱包流程。

购星、销毁、继续、领奖、市场激活、上架、购买、取消和授权均须先预览并得到确认。每次确认绑定钱包、网络、部署、NFT／接收人和金额；后续交易不能继承上一次同意。拒签和执行失败不推进奖励；超时先恢复原交易，不自动重发。

不存储私钥、助记词或共享钱包会话；公共服务只读，不代用户签名。钱包或网络变化后清除旧预览与确认。

## 状态与资源

从网站根目录（保留子路径）的 agent-manifest.json 发现 Skill、规则、能力、ABI 及模块入口。纯静态网站使用 api/rules.json 和 api/capabilities.json，不宣称存在动态 /api/game。配置可信 ABI 与 RPC 后可由 Adapter 直接读取；缺少这些能力就明确显示不可用。

水果市场使用独立配置，未配置时仅为标注清楚的布局示例，不能上架或购买。水果迷阵保留入口及规则预览，暂停页面跳转与链上执行。

## 展示规则

累计购买六枚 Star 或第三档奖励确认领取后，隐藏购星入口。购买次数取累计记录，转出和销毁不恢复额度。份额、阶段与领奖金额来自合约，不能固定写成全局 10/10 或剩余 10,000 份。

测试和部署边界见项目验证报告；支持通用 Skill 不代表已经验收所有宿主的钱包或 UI。
