# 九果迷阵 · 赛季合约初版

状态：已实现独立合约与测试，尚未进行第三方审计或公开网络部署。前端继续是模拟版，本提交不把模拟支付切换为真实支付。

## 部署结构

只需部署 `NineFruitsSeason(shapeToken, fruitNFT, agentRegistry, admin)`。构造函数同时创建自己的 `NineFruitsGravityVerifier` 和 `NineFruitsMedal`，共三个独立地址。通过 `verifier()` 和 `medal()` 获取子合约地址。没有代理、升级入口或管理员更换验证器的接口。

- `NineFruitsSeason`：资金、入场、挑战、排名、资格和领取。
- `NineFruitsGravityVerifier`：只读重放；无重力穿星星、无补充、仅水果交换立即匹配，连消不另计步。
- `NineFruitsMedal`：单一合约覆盖所有赛季，永久不可转让、不可批准转让、不可销毁。
- `NineFruitsTitle`：内联 UTF-8 标题校验库，不需要另行部署。

原有 Game、Token、NFT、Reserve 和 Liquidity 代码不修改。新模块只有 ERC-20 转账权限，没有原代币的铸币权限，也不调用旧 NFT 的销毁入口。

## 固定经济规则

- 第 N 季赞助金额恰好为 N BNB，一个钱包全额支付；下一季仅在上一季已经上传并开启后开放赞助，不需要上一季关闭。
- 冠名标题为 1–16 个合法 Unicode 码点，禁止 ASCII 控制符和全 ASCII 空格标题。
- 可选一种管理员兼容名单中的 BSC 代币，每份使用最小单位计数，提前一次存入 90 份。转出者扣款和合约实收均必须精确；不支持转账税或额外发送者费用。
- 冠名后目标 8 小时内发布。超过后继续等待，管理者仍可发布，不自动退款、取消或开启。
- 开启后永远开放。所有未分配和未领取余额继续为该季保留，没有任意提款或跨季挪款入口。
- 入场先转入固定 DEAD 地址 10,000 枚 3SHAPE；当前原代币 decimals=18，构造函数核对这一点。
- 每次有效玩家交换 1 枚 3SHAPE，完整清空并结算时统一转入 DEAD。检查玩家实际扣款和 DEAD 实收精确。自动下落和连消不收费。黑洞转账不减少 ERC-20 totalSupply。
- 第一名 30% BNB；第 2–9 名各获得 floor(剩余70%/9)；第 10 名获得同一份额加整除余下的 0–8 wei，总额恰好用完。
- 第 11–100 名仅在该季配置附加代币时，各获得固定一份代币。第 101 名以后无资金奖励，但仍有勋章。

## 状态与入口

1. `sponsor(id,title,token,perPerson)`：任何地址可调用，精确附带 N BNB。token 为零时 perPerson 必须为零；否则需先授权全部 90 份代币。单季只有一次有效冠名，失败整笔回滚。
2. `publish(id,board,solutionCommitment)`：管理者或受限发布者调用。必须先足额冠名。链上检查初始无三连、重力稳定、八种水果各至少三枚且至少一个星星，发布后棋盘和奖励不可改。
3. `start(id,nftIds[9])`：持有 .ai、九种 NFT，以及上一季勋章（S1 除外）。逐个检查真实 ownerOf/kind，种类不能重复。门票成功支付才保留挑战状态。
4. `abandon(id,nonce)`：玩家主动放弃，无退款。挑战没有有效期；关闭网页不是链上放弃。新挑战编号递增，旧编号无法结算。
5. `settle(id,nonce,path,nftIds[9])`：重新核验当前资格，从合约保存的棋盘重放，确认全部清空。验证、步数付款、关闭挑战、登记一次排名、发放勋章原子完成。失败均回滚，但先前已成功支付的门票不退。
6. `claimBNB(id,recipient)` / `claimToken(id,recipient)`：玩家领取自己的额度，可以指定接收地址，解决钱包不接收 BNB 的问题；不能领取其他钱包的记录。领取不再要求继续持有入场 NFT/.ai，以免已赚取的权益被后来持有状态冻结。

原有 NFT 不支持按种类查钱包余额，因此要求玩家提供九个 tokenId，检查种类位图完整覆盖 1–9，不扫描全局 NFT。

`path` 每个交换两个字节，格子编号从 0 开始、横向排列。只有水果与水果交换并立即形成至少三连才有效。6×6 最多 12 次有效交换，所以拒绝超过 24 字节的路径并非额外人为游戏限制。先合并横竖消除集合，再分列、以星星为界下落，直至稳定。验证器自己计算步数，忽略任何前端分数/计时。

## 勋章和外部回调

结算成功自动发行不可转让 ERC-721 勋章，同一钱包同季仅一枚；下一季直接核验这枚勋章，不依赖前端或数据库。链上 tokenURI 包含赛季、通关区块、实际交换次数、排名和 puzzleId。

发行使用 `_mint`，有意不调用接收者回调：勋章永久绑定完成挑战的钱包，没有转赠或销毁行为，不让不兼容的 NFT 接收回调阻塞资金结算。BNB/赞助代币另外自行领取，单次领取失败保留重试资格。

资金入口和领取均 nonReentrant；转账发生前更新本季状态，任何失败整体回滚。ERC-20 发奖同时检查奖池实际扣款和接收者实收；不精确或代币暂停时只影响该代币领取，不影响 BNB、已登记成绩或别的资产。

## 管理权限与信任边界

采用 Ownable2Step，建议 admin 为经过验证的多签。可添加/撤销发布者和兼容代币名单；禁止放弃所有权，以免主动丢掉未来发布能力。管理员不能改费用、奖励比例、已开赛棋盘、排名或验证器，也不能提取奖池。

必须保留的信任边界：

- `solutionCommitment` 是离线求解记录的哈希，**不是链上有解证明**。管理者必须先运行完整求解重放，再发布；恶意/错误管理者仍可能发布结构合法但无解的棋盘。
- 公共确定性棋盘可被复制、提前求解和机器人竞争。该版本没有 commit-reveal，不宣称防止所有抢跑；玩家仍须自己满足资格、付门票及结算费。
- 兼容名单是人工审核，不能保证外部代币未来不会暂停、升级、拉黑或重定基准。精确转账检查拒绝异常付款，不提供管理员强制代币退款/替换机制。
- 超过 8 小时继续等待是已确定规则；如果管理者永久失联，尚未发布赛季没有退款通道。正式冠名前必须把这一规则展示清楚。
- 任何直接误转/强制转入本合约的额外资产没有救援提款入口。不要向非 sponsor 入口转钱。

## 复现与部署准备

```sh
npm run compile:season
npm run test:season
npm run test:gravity
npm run test:season:fork
```

Fork 工具只允许向上游发送只读 RPC。官方 .ai 状态来自 BSC；原版 Token/NFT 和新模块仅部署于本地 Fork，持有人仅本地模拟，没有公开链交易。

你设计棋盘后，准备私有 JSON：`{"board":[36个数字],"solution":[[from,to],...]}`。执行：

```sh
npm run verify:season:puzzle -- <私有棋盘和解法.json>
```

工具检查完整解法并输出 packedBoard、solutionCommitment 和实际步数，不输出解法。真实比赛不要公开这个私有文件；仓库中的研究样例已公开答案，不能直接拿来办奖金赛。

复制 `config/nine-fruits.example.json`，填写已核实的原版代币、NFT 和多签地址。主网 .ai 必须是原项目的官方注册表。然后：

```sh
npm run prepare:season -- <已核实的部署配置.json>
```

仅生成未签名创建数据，不访问 RPC、不接收私钥、不发送交易，也不会验证输入地址对应的线上代码。实际部署前仍需独立核对依赖字节码/接口、管理员、多签和交易网络，并另行获得主网部署授权。

新模块的编译产物在 `artifacts/season/`（忽略入库）。合约大小、Gas 和测试证据见 `reports/season/`。前端真实合约适配尚未接入。
